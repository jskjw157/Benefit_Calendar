# Benefit Calendar - 수익화 모델 실현 가능성 분석

> 작성일: 2026-03-22
> 프로젝트: Benefit Calendar (청년/자영업자 대상 정부 혜택 캘린더 서비스)

---

## 결론: "가능하다. 단, 조건부."

수익화 자체는 가능하지만, 현재 MVP 상태에서 바로 가능한 것은 아니다. 데이터 확보와 사용자 확보라는 두 가지 선결 과제를 먼저 해결해야 한다.

---

## 1. 시장 수요 검증 현황

| 서비스 | 수치 | 시사점 |
|--------|------|--------|
| 카카오뱅크 정부지원금 찾기 | 50일 만에 50만 명, 일평균 1만 명 신규 | 시장 수요 실재 |
| 삼쩜삼 | 가입 2,000만, MAU 660만, 환급 8,000억 원 | 수익화 모델 검증 |
| 토스 숨은 정부지원금 | 2024.8 서비스 종료 | 수익화 없이 지속 불가 |

시장 수요가 실재한다는 것은 확실하다. 문제는 "어떻게 돈을 버느냐"이다.

---

## 2. 수익화 모델 4가지 평가

### A. 프리미엄 구독 (Freemium) - 가장 현실적

| 항목 | 내용 |
|------|------|
| **선례** | 커넥트웍스, kfund.ai |
| **적용 가능성** | 높음 |
| **난이도** | 중 |

**무료 티어:**
- 혜택 검색, 기본 캘린더, 3개까지 북마크

**유료 티어 (월 3,900~5,900원):**
- 무제한 북마크 및 상태 추적
- AI 맞춤 추천 고도화
- 마감일 알림 커스터마이징
- Google Calendar / Apple Calendar 동기화
- 서류 체크리스트 관리

**현재 코드베이스 기반:**
- `UserBenefit` 모델이 이미 BOOKMARKED/PREPARING/APPLIED/RECEIVED 워크플로 지원
- `recommendation-engine.ts`에 기본 추천 엔진 구현
- DB에 `notification_lead_days`, `notification_channel` 컬럼 존재
- 프리미엄 제한 로직만 추가하면 됨

**리스크:** 한국 시장에서 정보 서비스 월 구독료 지불 습관이 약함. 전환율 2~5% 가정 시, MAU 10만 명 기준 월 매출 780만~2,950만 원.

---

### B. 성과 기반 수수료 - 꿈은 크지만 비현실적

| 항목 | 내용 |
|------|------|
| **선례** | 삼쩜삼 (환급금 10~20%) |
| **적용 가능성** | 낮음 |
| **난이도** | 극높음 |

삼쩜삼 모델을 혜택에 적용하려면 실제 혜택 신청을 대행해야 한다. 그러나:
- 정부 혜택 신청은 각 기관 사이트에서 개별 처리 (표준 API 없음)
- 본인 인증/공인인증서 등 개인정보 위임 문제
- 대리 신청에 대한 법적 규제 리스크

**현 단계에서는 비현실적.** 향후 정부 API 개방이 진행되면 재검토 가능.

---

### C. B2B API 라이선스 - 중장기 모델

| 항목 | 내용 |
|------|------|
| **선례** | entitledto (영국) |
| **적용 가능성** | 중간 |
| **난이도** | 높음 |

- 복지관, 청년센터, 대학 취업지원센터에 혜택 매칭 엔진을 API로 제공
- 지자체 웹사이트에 혜택 캘린더 위젯 임베드

**현재 코드베이스 기반:** NestJS API가 REST로 구조화 (`/api/v1/benefits`, `/api/v1/users/me/benefits`), Swagger 문서화 계획 중.

**리스크:** B2B 영업 필요, 데이터 수집 파이프라인(현재 수동 샘플 10개)이 대규모 확장 필요.

---

### D. 광고/제휴 커미션 - 가장 빠르게 도입 가능

| 항목 | 내용 |
|------|------|
| **선례** | 삼쩜삼 (세무사 연결) |
| **적용 가능성** | 높음 |
| **난이도** | 낮음 |

- 혜택 상세 페이지에서 관련 금융 상품 연결 (청년 전세대출 혜택 -> 은행 대출 상품 제휴)
- 세무/법무 전문가 연결 커미션
- 교육/자격증 혜택에서 교육 플랫폼 제휴

**현재 코드베이스 기반:** 혜택 상세 페이지(`app/benefits/[benefitId]/page.tsx`)에 `applicationLink` 외부 링크 존재. 제휴 링크 추가는 기술적으로 간단.

**리스크:** 트래픽 규모가 작으면 광고 단가 낮음. MAU 최소 5만 이상 필요.

---

## 3. 현재 MVP에서 수익화까지의 갭

| 영역 | 현재 상태 | 수익화에 필요한 상태 | 갭 크기 |
|------|----------|-------------------|---------|
| **데이터** | 샘플 10개 (seed.ts) | 최소 500개+ 실제 혜택 데이터 | **극대** |
| **사용자 규모** | 0명 (개발 중) | 프리미엄 전환: MAU 5만+ | **극대** |
| **AI 추천** | 클라이언트사이드 룰 기반 | 서버사이드 ML 기반 개인화 | 대 |
| **알림 시스템** | DB 스키마만 존재 | 실제 이메일/푸시 발송 | 중 |
| **결제 시스템** | 없음 | PG 연동 (토스페이먼츠 등) | 중 |
| **인증** | 이메일/비번 JWT | 소셜 로그인 (카카오, 네이버) | 소 |
| **캘린더 동기화** | 자체 캘린더 뷰만 존재 | Google/Apple Calendar 연동 | 중 |

**가장 큰 병목은 "데이터"이다.** 현재 하드코딩된 10개 혜택으로는 어떤 수익화 모델도 작동하지 않는다. 정부24 API, 온통청년 데이터, 중소벤처24 공고를 크롤링/수집하는 파이프라인이 선결 과제이다.

---

## 4. 단계별 수익화 로드맵

### Phase 1: MVP 완성 (0~3개월)

**목표:** 얼리 어답터 1,000명

- [ ] 실제 혜택 데이터 500개+ 수집 파이프라인 구축
- [ ] 소셜 로그인 추가 (카카오, 네이버)
- [ ] 실제 알림 발송 구현 (이메일, 푸시)
- [ ] 서비스 런칭 및 초기 사용자 확보

### Phase 2: 성장 (3~6개월)

**목표:** MAU 1만, 유료 전환 3% = 월 구독 수익 ~120만 원

- [ ] 프리미엄 구독 도입 (무료/유료 티어 분리)
- [ ] Google Calendar 동기화 (유료 기능)
- [ ] 제휴 링크 시작 (금융 상품, 교육 플랫폼)
- [ ] PG 결제 시스템 연동

### Phase 3: 확장 (6~12개월)

**목표:** MAU 5만, 월 매출 1,000만 원+

- [ ] AI 추천 고도화 (서버사이드 ML)
- [ ] B2B API 시범 제공 (지자체 청년센터)
- [ ] 전문가 연결 커미션 모델
- [ ] Apple Calendar 동기화

## 6. 솔직한 평가

### 긍정 요인

- 시장 수요가 입증됨 (카카오뱅크 50일/50만 명)
- "마감일 캘린더 관리"는 진짜 공백 지대 - 경쟁자 중 아무도 안 하고 있음
- 현재 코드베이스 아키텍처(NestJS + Prisma + Next.js)가 확장 가능한 구조
- 기존 DB 스키마가 이미 알림/워크플로를 고려한 설계

### 부정 요인

- 토스가 수익화 실패로 종료한 선례가 있음
- 데이터 수집 파이프라인이 전무한 상태 (현재 수동 10개)
- 1인 혹은 소규모 팀으로 데이터 수집 + 서비스 운영을 동시에 하기 어려움
- 카카오뱅크가 캘린더 기능을 추가하면 브랜드/배포력에서 압도적 열세

### 최종 판단

**프리미엄 구독 + 제휴 커미션의 조합이 가장 현실적인 수익화 경로이다.**

다만, 수익화 이전에 **데이터 확보**와 **사용자 확보**라는 두 가지 선결 과제를 반드시 해결해야 한다.

현 MVP 상태에서 수익화까지는 최소 6개월의 추가 개발과 운영이 필요하며, "무료 사용자 5만 명"이라는 임계점을 넘기 전까지는 투자(시간/비용) 회수가 어렵다.

**핵심 우선순위: 데이터 파이프라인 구축이 가장 급선무이다.**
